# Shared client crate

Living notes for `crates/relay-client`. It holds what `apps/relay-cli` and `apps/relay-desktop` genuinely share over `relay-api`, and nothing toolkit-specific (no clap, ratatui, egui or tray). It depends only on `relay-api` (and `relay-io`), so it builds and tests without the engine.

| Module | Role |
|---|---|
| `command` | `Command` (every engine mutation), `CallTarget`, `CallAction`. Call-bound commands carry the controller generation; the transmit mode of `SetTransmit` is itself the microphone consent (no separate flag) |
| `wire` | The one place commands become RPCs: `send`, `mutation` (fresh idempotent operation id), `acquire_generation` (lease, optional explicit takeover), `open_telemetry`, `connect_registered` |
| `operation` | `settle` polls until an operation leaves `ACCEPTED`, over the `OperationSource` trait (a client, a client behind a lock taken per poll, or a test fake) |
| `endpoint` | `RELAY_TCP_PROFILE`, `RELAY_SOCKET`, per-user default, `describe`. Flags stay in the CLI |
| `meter` | dBFS to 0..1 bar fill (60 dB floor) |
| `daemon` | `ensure_running(&Endpoint, &StartOptions)` starts the daemon unless one answers: an advisory file lock at `<endpoint>.start.lock` makes concurrent callers start one; `daemon stop` in this process sets a flag so a later `ensure_running` refuses (`EnsureError::StoppedByRequest`); `StartOptions::autostart()` passes `--idle-exit` (300 s or `RELAY_IDLE_EXIT_SECS`); failures carry the log tail. Launcher for the separate `relayd`: `locate` (explicit, `RELAY_DAEMON_BIN`, next to the executable, `PATH`), `start` (detached: own process group, or `DETACHED_PROCESS` on Windows; output to a log file; waits for the endpoint with a bounded timeout; returns `Launched`, `AlreadyRunning`, `BinaryNotFound` or `FailedToStart` with the log tail), `stop` (registers with `admin`, calls `Shutdown`, waits for the endpoint to vanish), `reachable`, `log_tail`. No dependency on `relay-engine`. |

## What stays in the apps
- Validation differs by design (CLI: finite gain 0 or more, non-empty name; desktop: gain 0..4, 1 to 64 printable characters, avatar size and type, known ids), so it is not forced into one rule set.
- Lease policy: the CLI acquires before every call mutation (optional `--takeover`); the desktop reuses the generation from state and never takes over.
- Error mapping and exit codes (CLI `CliError`) versus `EngineError` (desktop).
- Supervisors: the CLI feed forwards `Update`s with a fixed retry and the `Control`/`Subscribe` traits for fakes; the desktop mirrors state into a view model with exponential backoff and `Operations`/`Engine` ports. Their consumers differ, so only the wire and settle code below them is shared.
- Name and id resolution (`commands/resolve.rs`, `names.rs`), view models, transmit text, and hotkey/PTT status (the desktop has no hotkey surface) are single-client.

## Daemon revision and replacing a stale daemon
`RelayClient::daemon_revision()` (relay-api) returns the daemon's build and API revision from `GetInfo` as `relay_api::Revision`; `Revision::local()` is this binary's, `is_current()` compares the API revision only. `relay_client::refresh` decides whether to replace a running daemon: `refresh(&mut impl Daemon, Policy)` is the pure decision (tested with a fake), `refresh_endpoint` the real one. It probes the daemon (registers with `observe`, reads the snapshot: a call that is preparing, ringing, connecting, connected or interrupted makes it busy), and with `Policy::StaleOnly` (the CLI) replaces only a daemon whose API revision differs (the build text is display only: binaries of one tree can carry different commit or `-dirty` text, so it never decides), with `Policy::AnyIdle` (the desktop app at launch) any idle daemon. A busy daemon is never touched (`Outcome::KeptBusy`). Stop and start run under the per-endpoint start lock that `ensure_running` uses, so a client that autostarts at the same moment waits for the replacement and a second replacer finds the lock held (`Outcome::Contended`, nothing done). A daemon that does not stop within the wait is an error (`RefreshError::StopTimedOut`), reported once, and no second daemon is started. Other attached clients do not prevent a replacement; they reconnect through their own supervisors.

## Starting daemons and the keychain prompt
`daemon::ensure_running(_with)` starts a daemon under the per-endpoint start lock (an advisory file lock the OS releases when its holder dies, so a stale lock file never blocks) and then waits for it to be *ready*. A daemon whose endpoint answers is running, whatever it reports: the launcher never kills or restarts it, a second attempt attaches to it instead of spawning another, and the lock is released as soon as the endpoint answers (waiters poll the endpoint, not only the lock). `wait_ready` asks `GetInfo`: while the daemon is `STARTING` (waiting for the system's keychain prompt) it keeps waiting up to `StartOptions::startup_timeout` (300 s) and calls the progress callback of `ensure_running_with` when what it waits for changes; it fails only when the daemon reports `FAILED` (`EnsureError::NotReady(NotReady::Failed { reason, detail })`), stops answering (`Gone`) or the cap passes (`TimedOut`; the daemon is left running). `StartOptions::ready_timeout` (10 s) now only covers the endpoint appearing, and a daemon that misses it is not killed. `refresh` never replaces a starting or failed daemon (`Outcome::Starting`).

## Tests
`crates/relay-client/tests/`: `startup_wait.rs` runs the launcher against a `fake-relayd` that serves the start-up switch (waits while `starting`, one process, a second attempt attaches, `failed` reports the reason and `RetryKeychain` recovers the same daemon, running out of patience leaves it running, `register` is refused while starting); `wire.rs` runs each command against an in-process engine on a Unix socket, `settle.rs` covers polling and timeout with a fake source, `endpoint.rs` and `meter.rs` the pure helpers, `refresh.rs` the replacement decision (idle stale, matching, busy, stop timeout, start failure, held lock), `revision.rs` the revision read from a connection, `daemon.rs` the launcher against a stand-in `fake-relayd` binary (start, already running, missing binary, early exit with log tail, timeout, slow start, own process group, lookup order). Each app keeps tests for its own UI, CLI and supervisor logic.

## Push-to-talk worker

`relay_client::ptt::PttWorker` is the one implementation of hold-to-talk. The CLI's global key, the desktop hotkey and hold button and Android's hold button all use it. API: `PttWorker::spawn(handle, endpoint, resolve)`, then `press(call_hex)`, `release()`, `cancel()` (all cheap, from any thread, nothing blocks) and `states()` (a `watch` of `PttState`: `Idle`, `Transmitting`, `Gated`, `NoTarget`, `Rejected{code}`, `Failed(reason)`, taken from the engine's acks). `resolve` is a plain function `Fn(&str) -> Option<PttTarget>` that the caller supplies; `relay_ui::ptt_target::resolver(hub)` is the UI's (a live push-to-talk call that the UI client controls and an attached link) and the CLI supplies the call it bound.

- The worker opens its own connection and adopts the controlling client's registered context (`RelayClient::adopt_context`), because the engine accepts a press only from the controller. Taking the lease over would reset the call's transmit route.
- `press` sends `InputControl` `PRESS` with a 400 ms lease, renews every 150 ms and `release` sends `RELEASE` (the engine's release delay applies). A press for a call `resolve` does not accept sends nothing (`NoTarget`) and never changes the mode.
- `cancel`, dropping the worker, a call that is no longer a controlled push-to-talk call (ended, left push-to-talk, new controller generation, detached client; checked on every renewal) and the stuck-key limit (a press held for 60 s without a key-up) close the stream. The engine treats that as an immediate release without the release delay. A refused renewal ends the press. If the process dies the lease lapses within 400 ms.
- Tests: `tests/ptt.rs` against a scripted engine on a socket (renewal and sequences, no target, cancel, drop, call change, generation change, refusal, gated, stuck key with paused time). End to end with a real engine and fake media: `apps/relay-android` `host::ptt_tests` and `apps/relay-desktop/tests/ptt_engine.rs`.
