# Shared UI (`relay-ui`)

`crates/relay-ui` holds the Relay screens and everything behind them so more than one shell can reuse them: the desktop app today, an Android app (eframe through `android-activity`) later. It depends on `egui` (no `eframe`, `tray-icon` or `rfd`, no windowing), `relay-client`, `relay-api`, `tokio` (a `Handle` only, never a runtime), `image` and `qrcode`. It is a workspace member but not a default member, like `relay-desktop`.

| Task | Command |
|---|---|
| Tests | `cargo test -p relay-ui` |
| Lints | `cargo clippy -p relay-ui --all-targets --no-deps -- -D warnings` |

## What lives here
- Logic, no toolkit: `engine` (port traits), `relay_link` (adapter over `relay-client`), `supervisor`, `apply` / `convert` / `model` (wire to view model), `hub`, `controller` and `channels` (validation), `emitter` (bounded cadence, tray summary), `format`, `viewmodel`, `avatar` (default image, bounded cache), `imaging` (bounded decode, `avatar_check`), `host_options`, `qr`, `inbox`, `mock`. The engine link stays here (not in `relay-client`) because it implements the UI's `Engine` port; dependency direction is `relay-ui -> relay-client -> relay-api`.
- Shell glue: `shell` (the `Shell` and `FilePicker` traits), `actions` (`Shared`, `ShellSink`, `Actions`), `tasks` (avatar fetch, connection info, invite, picker jobs on the shell's runtime handle).
- Look and layout: `theme` (colour, spacing and type tokens, light and dark styles; egui's default `ThemePreference::System` follows the OS hint), `layout` (`LayoutClass`, `Page`, touch size).
- Drawing: `ui/` with `RelayApp`, `kit` (cards, titles, help text, buttons), `sidebar` (regular layout) and `nav` (compact bottom bar), the pages `home` (Calls), `people` and `channels`, `chat` (where a call's chat appears) with the `messages/` widgets, `call_card`, `incoming` (the ringing prompt) and `banners` (notices) above every page, `settings/` (one file per category), textures (avatar cache). `capabilities` turns the shell's flags into `Capabilities` and decides which `SettingsCategory` entries exist.

## Shell contract
A shell supplies a tokio `Handle` and an `Arc<dyn Shell>`:

| Method | Purpose |
|---|---|
| `pick_image` (`FilePicker`) | Native image chooser; the shell checks the size (1 MiB) before reading and returns `PickedFile { name, bytes }`, or `Ok(None)` on cancel |
| `pick_directory`, `save_as`, `pick_file` (`FilePicker`) | Native folder, save-as and file dialogs that return an absolute path only (the daemon opens or writes it). Default methods are the documented stub for shells without filesystem paths (compact/Android: content URIs are not paths): they return `NO_PATHS` and the UI shows it as a notice. Desktop implements them with `rfd` |
| `open_url` | Opens a link in the browser; called only after the link confirmation dialog. Default: does nothing |
| `copy_text` | Clipboard |
| `request_repaint` | Called by writers after new data, never per frame |
| `window_visible` | Hint polled once per frame; meters are produced only while true |
| `show_window`, `hide_window`, `quit` | Window actions; quitting never stops the daemon. Mobile shells may ignore show/hide |
| `hides_to_tray` | Whether closing hides the window, so the UI can say so |
| `host_options` | Optional `HostOptions` (language, call notifications, start at login) drawn under Settings, Language and Startup; `None` on shells without them |

Wiring (see `apps/relay-desktop/src/main.rs`): build `Hub`, `SessionSlot`, `Controller`, `Shared`, then `Actions { controller, hub, shared, runtime, shell }`; spawn `emitter::run` with a `ShellSink` and either `supervisor::supervise(RelayLink::new(resolve_endpoint), ..)` or `mock::run`. Per frame call `RelayApp::begin_frame(ctx)` then `RelayApp::ui(ui)`.

## Auto-start and quitting
`autostart::AutoStart` (setting, `RELAY_NO_AUTOSTART`, user quit, 3 starts per 60 s, exponential backoff) is pure and tested without a clock; `supervise` takes the `Shell` and `Arc<AutoStart>` (`Shared.autostart`). `Link::Starting` is the honest "starting" state. `Actions::quit_app` hangs up `format::own_live_calls` (calls with `controlled_by_me`, not ended) for up to 2 s before `Shell::quit`; `format::close_note` and `format::quit_prompt` are the texts and name active calls. `Command::SetAutostart` / `Controller::set_autostart` store the preference.

## Pages and Settings
Four pages: Calls (running calls, then the people nearby with Call; when nobody is there, what to do), People (a discoverability card, the "Connect a device" section with this device's address and QR code, the paste field to add a device by connection string, then nearby and other trusted devices, Forget this device behind a confirmation through `Controller::forget_peer` / `Command::ForgetPeer`), Channels and Settings. Messages are not a page: they belong to a call and open from its card or its history row (see "Session messaging UI"). Notices and the incoming-call prompt are drawn in a strip above the page, so a ringing call is visible and answerable on every page, Settings included. Technical detail (keys, ids, counts) sits behind "Details".

Settings has eight categories, each a small file in `ui/settings/`: Profile, Audio, Push-to-talk, Calls, Privacy, Language, Startup, Advanced. Which exist follows `Capabilities` (no Language or Startup without `host_options`; Startup also appears where the app has window controls; the daemon controls in Advanced need `can_manage_daemon`; the hotkey and delay wording follows `has_global_hotkey` / `has_talk_button`; "Hide window" and "Quit this app" only exist where the user closes a window, never where the system keeps the app alive, `Capabilities::window_controls`). Regular layout: categories in a list on the left, the chosen one on the right, Back (or Esc) returns to the page Settings was opened from. Compact layout: the category list, then one category under a Back button. The chosen category is remembered; state a category holds (hotkey draft, pending confirmations) is dropped when it is not on screen.

Connect a device (`ui/connect.rs`, top of People, under the discoverability card): the section shows this device's connection string (selectable), Copy address, the QR code, and addresses, port and fingerprint behind Details; the paste field ("Add a device by address") is the next card, so exchanging details is one place. It is open while no device is known (`rows.is_empty()`) and collapsed otherwise; clicking the header stores the choice in `Local::connect_open`, which then wins. Collapsed, Copy address stays under the header. The page asks the daemon for the string when it is first drawn and drops the string and QR texture when another page is shown. Tests: `tests/people_connect.rs`.

Discoverability (`ui/visibility.rs`, `viewmodel::discoverability`): Discoverable (green, advertised so others on the same network can find and call this device), Private (neutral, not advertised; only someone with the address can call) or Not advertising (amber, with the link state as the reason). The engine exposes the stored preference (`Settings.advert`, `privacy.advert_mode`) and who may ring (`Settings.inbound`) but no live "is advertising" flag; the daemon advertises only while a client is attached (`docs/engine.md`, presence), so the state is the preference combined with `Link::Connected`. A chip shows it in the sidebar identity block (full sentence as hover text); the People card repeats it in one line, adds a "who can ring me" line when it is limited to channel members, and has a button (Go private / Make discoverable, disabled until the daemon is connected) that calls `Controller::set_privacy`, the same control as Settings, Privacy. Tests: `tests/discoverability.rs`, `tests/people_fit.rs`.

The sidebar is `theme::SIDEBAR_WIDTH` (216 points) wide; the name in it uses `theme::TEXT_SIDEBAR_NAME` (14) and is cut with an ellipsis (full name on hover). The compact layout has no sidebar.

Keys: Esc closes the open chat, else leaves Settings (or the category on a phone), unless a drop-down is open; Ctrl/Cmd+1 to 3 open Calls, People and Channels; Ctrl/Cmd+, opens Settings. Tests: `tests/nav.rs`.

Not available in the UI because the model or API has no such thing: marking a device verified (`DecidePeerTrust` needs the full key digest, which the view model does not carry), noise or echo switches. The call duration is counted from when this app first saw the call connected and is redrawn with other changes, not on a timer (the UI never requests repaints).

## Responsive layout
`LayoutClass::for_width` picks compact below 600 points (phone: one column, bottom navigation with Calls, People, Channels, Settings, 44 point minimum touch targets and a larger body size) and regular otherwise (desktop: a sidebar with Calls, People, Channels and the Settings button, one page at a time, content at most 720 points wide). The class is chosen in `begin_frame` from the content width; the style is reinstalled only when the class changes (one repaint, no per-frame work). Tests in `crates/relay-ui/tests` cover the breakpoint, touch sizes, themes, every compact page, and run whole frames with a fake `Shell` and no window.

Compact layout rules (width-based, not tied to a platform). Rows never rely on `available_width` being enough: button groups use `widgets::button_row` (stacked full-width buttons in touch style, wrapping on desktop), text fields take `field_width`, drop-downs and sliders put their label above and fill the row (`combo`, `slider_row`), cards and channel/peer rows put their buttons under the text. Bottom tabs shrink their font to fit and then cut with an ellipsis, never mid-word, and show the full name as hover text (the page heading shows it in full too). Tap targets are 44 points; labels are not selectable in touch style, and a hint that would be hover-only (`widgets::hint`, the level meter) is shown as a visible line instead. Text may grow 40% in other languages: tests run English, German and Russian at 360x800 and 320x640 points and 2.6 pixels per point.

Optional `Shell` hooks, all with desktop-safe defaults: `safe_area_insets() -> Insets` (points covered by status bar, cutout, gesture bar, side cutouts; the app keeps its content out of them), `keyboard_height() -> f32` (soft keyboard height from the screen bottom, 0 when hidden; the app pads the bottom, hides the tabs and scrolls a focused field into view once), `has_global_hotkey()` (default true; false drops the hotkey panel and wording), `has_talk_button()` (default false; true shows a large press-and-hold talk button on push-to-talk calls, reported through `push_to_talk(call_id, pressed)`, and the hotkey note says so), `runs_in_background()` (default false; picks the "leaving keeps calls going" wording when there is no tray). The talk button follows pointer-down, so touch works, and a held button that disappears is released. Tests: `phone_overflow`, `phone_tabs`, `phone_insets`, `phone_touch`, `phone_talk`. 

## Rules kept
- Idle zero repaint: the UI never requests a repaint itself; an idle screen asks for none (tested at phone and desktop widths).
- Bounded cadence: emitter at 25 Hz, tray text at most once a second, state marked dirty only when changed.
- Secrets (`relay_client::Secret`) stay redacted in `Debug`; UI-only state is deliberately not `Debug`.

## Not done
- No Android shell exists yet; the touch layout is untested on a device or with a real touch screen. `FilePicker` has no Android implementation (content URIs rather than paths are the expected shape: return the bytes).
- No on-device or screenshot check of the compact layout; only window-less frames run.
- The mobile resource gate (CPU, RSS, battery) is unmeasured.

## Call history

The Calls page ends with a History section that is always drawn (`ui/history.rs`, rows from `history_view`, relative times from `history_time`): with nothing to list it shows "No call history yet". Each row is a card with the device's picture (or an initial in a circle when the device is no longer known), the name as it was at the time, a marker word (`Incoming`, `Outgoing`, `Missed`, `Declined`, `Not reached`, `Cancelled`; no icons), the relative time, the length for calls that connected (`m:ss`, `h:mm:ss`) and **Call back**, which is `Controller::start_call` like Call on the People page and is disabled when that device cannot be called now, with the same reason text ("This device cannot be called right now." for a device that is online but blocked or in a call, "Not reachable" otherwise). A missed call is drawn with its name and marker in the error colour. Twenty rows are shown; **Show more** adds twenty (`Local::history_shown`, the whole list is already in `AppState.history`). **Clear history** asks first ("Delete the whole call history on this device?", Clear history / Keep) and then sends `Command::ClearCallHistory`. When recording is off the section says that nothing new is recorded and the entries stay until cleared.

Relative times (`history_time::relative`, a pure function of `now`, the entry's time and a `LocalZone`): "Just now", "N min ago" under an hour, "N h ago" the same local day, "Yesterday, HH:MM" on the previous calendar day, "N days ago" up to six, then `YYYY-MM-DD`. `now` is `Shell::now_unix_ms` (default: the system clock) and the zone `Shell::time_zone`, so a shell or a test injects both; the page asks for a repaint every 30 s only while a shown row is under a day old.

The list reaches the UI through the supervisor: it reads `Operations::call_history` (`ListCallHistory`) when it connects and whenever `Settings.history_revision` changes (an entry was recorded or the list cleared), stores it in `AppState.history`, and keeps the last list when the connection drops. Settings, Privacy and trust has the **Keep call history** checkbox (`history.enabled`): it sends `SetSettings` through `Controller::set_history_enabled` and shows the daemon's per-key answer in the same words as the hotkey panel (`applied now`, ...); its value is `Settings.history_enabled`. Tests: `tests/history_time.rs`, `history_view.rs`, `history_screen.rs` (always present, every outcome, Call back, Show more, Clear confirmation, the switch, no overflow and 44-point targets at 720 and 360 wide in en/de/ru), `history_refresh.rs`. Privacy: `docs/config.md`, "Call history".

## Profile picture and trust hints
The picker accepts PNG, JPEG, WebP, GIF, BMP and TIFF by content, 1 MiB, 2048 x 2048, and refuses with the engine's wording (`docs/api.md`, "Avatar refusal texts"). "Discard" drops a pending choice only; "Remove picture" calls `Controller::clear_avatar` (`Command::ClearAvatar`) for the stored one. `Peer.fingerprint_short` (sanitised to hex and dashes, 24 characters) is shown under each peer and on the incoming-call prompt with the trust state, labelled as a way to tell devices apart, not to verify. Preferences the UI edits (display name, ring, release delay, autostart) already change live through their own commands; the push-to-talk hotkey panel (below) is the one place that uses `GetSettings` and `SetSettings`.

## Push-to-talk hotkey panel

Settings, Push-to-talk has the hotkey panel (`ui/settings/hotkey.rs`, state in `hotkey_settings::HotkeyPanel`, kept in `Local`). Opening it reads the two keys with `GetSettings` (`Operations::get_settings`, `Controller::hotkey_settings`): `hotkeys.push_to_talk` (the global accelerator, empty turns it off, at most 64 printable characters) and `ptt.release_delay_ms` (0 to 2000). A missing or malformed key is shown as an error, never defaulted. The user edits a draft; **Save** sends only the keys that differ through `SetSettings` (`Operations::set_settings`, `Controller::save_hotkey_settings`; nothing differing sends nothing, and values that cannot be valid are refused locally). The daemon's answer is shown per key exactly as given: `applied now`, `saved, takes effect after a restart (reason)` (the hotkey is read when the hotkey backend starts) or `rejected (reason)`. After a save the panel rereads the daemon, so the stored values it compares against are the daemon's; a rejected key stays in the draft until **Revert**. Closing the panel forgets its state. The slider above (`SetGlobalControls`) and this panel both change the release delay; the engine is the single source of truth. Tests with a fake daemon: `tests/hotkey_settings.rs`.

## Push-to-talk release delay

Settings, Push-to-talk has a slider for the push-to-talk release delay (0 to 2000 ms, step 10, shown as `N ms`; `release_delay_label` renders 0 as "Off (closes at once)"). Dragging keeps the value in `Local::release_delay_edit` and sends one `Controller::set_ptt_release_delay` on release (a `SetGlobalControls` with only `ptt_release_delay_ms`); values above 2000 are refused locally. `Settings.ptt_release_delay_ms` comes from the engine, and `describe_transmit` shows "Releasing" only while the engine reports both `effective_transmitting` and `releasing`. The mock engine round-trips the value. Settings, Calls also has checkboxes for the ring, ringback and connect/hang-up sounds, a ringtone volume slider (0 to 1, `Local::ring_volume_edit`, `ui/settings/ring.rs`) and a **Test ring** button. They call `Controller::set_ring_preferences` (a `SetGlobalControls` with only the ring fields; a volume outside 0..1 is refused locally) and `Controller::preview_tone` (the `PreviewTone` call: the daemon rings on its own output for 2 s). The app plays no sound itself. View-model tests: `tests/format.rs`, `tests/controller.rs`, `tests/mock.rs`.

## Session messaging UI

Design and daemon contract: `docs/session-messages.md`, `docs/api.md`. Logic is in `crates/relay-ui/src/messaging`, drawing in `ui/messages`, placement in `ui/chat.rs`.

- **Placement.** The chat is part of the call, not a page. Regular layout: the call card's **Messages** button shows a chat panel below the card (a fixed-height panel with a Close button) and toggles it; the same chat opens read only below a history row from that row's **Messages** button. Compact layout: the button opens a full-screen chat (the bottom tabs are hidden) with a **Back to the call** button (**Back** for a history chat). Only one chat is open at a time, Esc closes it, and leaving the Calls page closes it. A message arriving while the chat is closed only turns the button into **Messages (N)** (N received messages not yet shown, `rules::unread_count`); it never opens or takes focus. The incoming-call prompt stays in the strip above the chat. `MessagesUi::show(call_id, over)` draws the session of that call (`rules::session_of_call`: the live one, else the latest ended).
- **History rows.** A row's button is enabled unless the daemon is known not to hold the transcript (`rules::transcript_kept`): with a live feed and no session for the entry's `call_id` it is disabled and the row says "Messages from this call are no longer kept" (messages are memory-only; a daemon restart or eviction drops them). A row whose session exists shows **Messages: N**. While messaging is not connected nothing is known, so the button stays enabled and opening it connects, as opening any chat does. An ended call's chat has no composer (the existing "This call has ended" explanation with Export and Clear).
- **Connection.** Messaging uses its **own** `RelayClient` registered with only the `messages` capability (`messaging::link`), so transcripts are readable only by a client that asked. It is opt-in: opening a chat turns it on (unless the user turned it off on purpose); the Privacy panel has the checkbox and explains the grant. Turning it off disconnects and forgets every transcript held in the app. The choice is per run (not persisted).
- **State and resync.** `messaging::supervisor` follows state like the main supervisor: `ListSessions` -> `GetTranscript` (newest 5000 entries per session, `MAX_LOCAL_ENTRIES`) -> `WatchSession(after_revision = list revision)`. Applying events is idempotent so replays are harmless. A `SessionResync`, gap, error or stream end re-reads (same connection for a resync, reconnect with backoff otherwise); `PermissionDenied` shows the Denied state and retries every 30 s. Events are coalesced into one repaint per 40 ms; no timers run while idle.
- **Virtualized list.** `VirtualList` keeps estimated then measured row heights; only rows intersecting the viewport plus 200 pt are laid out (tested: 3000 messages draw a few dozen). Row heights are corrected by measurement and one repaint is requested only while they changed.
- **Drawing under a lock.** The panel draws while holding the `MsgHub` state lock (transcripts are never cloned) and records `Intent`s, dispatched afterwards by `Actions::dispatch`. Message text, file names and URLs are redacted from `Debug` of every messaging type, `MsgCommand` and `Intent`, and no tracing call includes content (`tests/msg_redaction.rs` greps TRACE output of a full run).
- **Markdown.** The daemon sends only stored text, so the client parses with `relay_messages::markdown::parse` once when an entry arrives. Bold, italic, inline code, flat lists, fenced code blocks (language label, **Copy** copies `CodeBlock::copy_text` exactly). A link shows the URL, an IDN or mixed-script badge, and clicking only opens a dialog with the real ASCII host, the decoded form, the warning and the full URL; "Open in browser" calls `Shell::open_url` once (`LinkGate`). Nothing opens or loads by itself.
- **Compose.** Enter sends, Shift+Enter adds a line (`rules::is_plain_enter`), a byte counter against 4096, and when sending is impossible an explanation instead (daemon off, permission off on either side, ended call, history full with **Export JSON** and **Clear** buttons). Failed sends return the draft to the box. **Send clipboard to call** asks the platform for a paste, shows the clipboard size and the destination call name (call id prefix with several calls), has no default with more than one live call, never truncates (over 4096 bytes is refused) and sends only after a button press.
- **Images.** Only inline images (at most 15 KiB, as the daemon enforces) are decoded: `relay_messages::image::inspect` first (refuses over 16 megapixels), then decode with an allocation limit off the UI thread, scaled to 384 px, textures in a 48-entry LRU (`avatar::TextureCache`; the `lru` crate was not adopted, see `docs/reviews/dependency-audit.md`).
- **File offers.** Cards show name, size, type guess, BLAKE3 short form, status and progress, warnings (executable name, large file, over the offer cap, free space needed), and the buttons Download (folder dialog -> `RespondOffer`), Reject, Cancel, Request/Approve/Refuse preview. After the call ends nothing can be downloaded. "Offer file..." sends the absolute path to the daemon, which opens it.
- **Pins and search** are local: pins go to the daemon as a local flag, search filters the held entries case-insensitively (text, file names, previews).
- **Honest states:** off (not opted in), connecting, capability denied, daemon unreachable, `messages.enabled = false` (with a button to switch it on), no sessions, call without a session, ended read-only transcript.
- **Mock mode** (`--mock`): `messaging::mock` seeds two live calls (a rich transcript with markdown, a lookalike link, an image, offers, a failed message; a type `/fail` message to see Retry), an ended session and an ended session with 3000 messages. Export writes nothing in the mock.
- **Timestamps** are local time (`HH:MM:SS`, receiver clock) in the zone `Shell::time_zone()` returns (default `LocalZone::system()`, from `relay_io::localtime`, backed by `jiff`; daylight saving is applied per message). The shell or a test may return a fixed zone, so rendering is deterministic. The hover text (`rules::row_times`) gives the local date and offset with the UTC clock, then the sender's own claim in the same form. Stored and transported values stay UTC milliseconds. Tests: `tests/msg_local_time.rs`.

Tests: `tests/msg_rules.rs` (counters, compose gating, offer buttons, clipboard destination rule, link gate), `msg_virtual.rs` (virtualization maths), `msg_state.rs` (events, resync idempotence, bounds), `msg_supervisor.rs`, `msg_actions.rs`, `msg_image.rs`, `msg_redaction.rs`, `msg_mock.rs`, `msg_layout.rs` (both layouts draw every state, long history, idle zero repaint, clipboard dialog).

## Fonts
`fonts::install(ctx, language)` (called from `begin_frame` on the first frame and again whenever the language changes) replaces egui's font definitions: Noto Sans first for Proportional, then Noto Sans JP, KR, SC and Devanagari as per-glyph fallbacks in a per-language order (`fonts::order`: `zh-CN` puts SC first, `ja` JP, `ko` KR, `hi` Devanagari right after Noto Sans, everything else JP, KR, SC, Devanagari), then egui's own faces (emoji and symbols). Monospace keeps egui's face first and gets the Noto faces appended so CJK in code-style text renders. Files, subsets, sizes (3.1 MB total, Regular only), licences (OFL 1.1) and the rebuild command are in `assets/font/README.md`; the reasoning is in `docs/decisions.md`. Text shaping: egui 0.37 shapes every run with harfrust inside its own layout (see `docs/decisions.md`), so Devanagari conjuncts, matra reordering and reph apply to all text, including peer names, messages and editable fields, with nothing Relay-specific; `crates/relay-ui/tests/shaping_*.rs` pin this against the bundled face and the Hindi catalog. Visual check on screen is still open (`docs/gates.md`). Limits: shared Han characters use the first face that has them, which is the language's own face for `zh-CN`, `ja` and `ko` and JP otherwise. `crates/relay-ui/tests/fonts.rs` parses every face, asserts sample strings of all nine UI languages have glyphs and the per-language order; extend its table when real translations land.

## Translations
Every user-visible string goes through `tr!` (`crates/relay-ui/src/i18n/`: `catalog.rs` Fluent lookup, `embed.rs` auto-discovering embed of every `localizations/*/*.ftl`, `lang.rs` languages, `locale.rs` system-locale matching, `picker.rs` picker order and labels, `check.rs` catalog checks). Catalogs are in the root `localizations/<lang>/<section>.ftl`. The active language is process-global (`i18n::active`, `set_active`); `RelayApp::begin_frame` asks `HostOptions::language()` and, on a change, switches it and reinstalls the fonts the same frame. `HostOptions` gained `language()`, `language_choice()`, `system_language()` and `set_language_choice()` (`None` = System, shown first as "System (Deutsch)"); the picker is in the "This app" panel (`ui/host_switches.rs`). View models and error types that used to return `&'static str` constants now return `tr!` results (`viewmodel::modes()`, `local::invite_ttls()`, `format::hotkey_note()`); `ControlError` and `EngineError` implement `Display` by hand so their text follows the language. `TraySummary` carries the language so a change redraws the tray. Engine text is shown as received. How to add a string or a language, the checks and the review gate: `docs/i18n.md`. Tests: `i18n_catalogs.rs` (the translators' check), `i18n_keys.rs`, `i18n_language.rs`, `i18n_switch.rs` (fake shell switches the language and the drawn text changes, per-key fallback).
